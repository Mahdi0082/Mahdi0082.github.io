About me

I’m Mahdi, a PhD student in Computer Science at Washington State University. My research asks how many machines can solve nested learning problems together, like tuning a model while it trains, when each machine keeps its data private and has its own constraints.

My work sits between theory and practice. I design algorithms and prove that they converge, and because I’m proficient in Python, I implement and test them myself, in experiments such as fairness-constrained learning. Before bilevel optimization I worked on applied deep learning, including medical imaging with Vision Transformers, and I still build applied projects alongside my research.

Research

Under review · ICLR 2027

FedBiC: Federated Bilevel Constrained Optimization

Many clients tune one model together while each keeps a constrained inner problem and its data private. The analysis gives convergence guarantees when only some clients take part in each round, and experiments cover fairness-constrained learning.

Paper (link after review)See the idea in the demo

What FedBiC adds

  • Its own constraints for every clientEach client’s inner problem can carry its own inequality constraints, such as fairness limits.
  • One problem instead of twoRewrites the nested problem as a single penalized one that clients can solve with ordinary gradient steps.
  • Works when clients come and goConvergence guarantees hold even when only some clients take part in each round.
  • Data stays with the clientThe server only ever receives gradients for the shared model, never data or inner variables.

Federated bilevel optimization, in miniature

toy model · 5 clients

Five clients, think hospitals or phones, each keep their own private data. Together they want one shared setting x that works well for all of them: that is the outer problem. How good x is for a client depends on the answer to that client’s own inner problem, which it solves on its own data. A problem nested inside another like this is a bilevel problem, and solving it without anyone sharing data is federated bilevel optimization.

  1. The server sends the current x to a few clients (they turn green).
  2. Each one works on its inner problem: its gray dot moves toward the hollow circle, the exact answer for this x.
  3. It sends back one gradient, a direction to move x. Its data never leaves it.
  4. The server averages those directions and moves x. On the server bar, the dot is x and the tick is the best possible value.
